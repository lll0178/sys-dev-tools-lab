## 二、实验一：含空格文件名的批量整理（q01）

### 2.1 完整脚本（scripts/q01.sh）

```bash
#!/bin/bash
set -e
SID=25030021043            # ← 学号
mkdir -p q01/input/docs q01/input/tmp
cd q01

# 1. 创建文件
printf 'alpha\nbeta\n' > 'input/docs/notes one.txt'
echo 'hidden' > input/docs/.secret.txt
touch input/tmp/empty.txt
printf '2026-08-24 10:00:00 INFO start\n2026-08-24 10:01:00 INFO stop\n' > input/run.log

# 2. 绝对路径 + 长格式列表（含隐藏文件）
pwd
ls -la input

# 3. 复制所有 .txt 并保留相对目录结构
mkdir -p "work/$SID"
(cd input && find . -type f -name '*.txt' -exec cp --parents {} "../work/$SID/" \;)

# 4. 权限：目录 750，普通文件 640
find "work/$SID" -type d -exec chmod 750 {} +
find "work/$SID" -type f -exec chmod 640 {} +

# 5. inventory.txt：相对路径 + 字节数
find "work/$SID" -type f -exec wc -c {} \; > inventory.txt

# 验证
ls -laR "work/$SID"   # -a 显示隐藏文件；目录 drwxr-x---，文件 -rw-r-----
cat inventory.txt
```

### 2.3 要点分析

- **空格处理**：`find -exec` 会为 `{}` 自动加引号、逐个传参，`cp --parents` 原样保留 `notes one.txt` 中的空格，不会把文件名拆成两个参数。
- **复制范围**：`.secret.txt` 以 `.txt` 结尾，属于"所有 .txt 文件"，被一并复制；`run.log` 不是 `.txt`，不复制；`tmp/empty.txt` 是空文件但后缀符合，也复制。
- **目录结构**：`find . -type f` 输出 `./docs/...` 形式路径，`cp --parents` 在目标下重建 `docs/`、`tmp/` 子目录，`./` 会被路径解析自动归一化，不影响结构。
- **权限**：目录 `750` = `rwxr-x---`（所有者全部权限，组可读可执行，其他无）；普通文件 `640` = `rw-r-----`（所有者读写，组只读，其他无）。
- **字节数核对**：`alpha\nbeta\n` 为 5+1+4+1=11 字节；`hidden\n` 为 7 字节；空文件 0 字节。

## 三、实验二：随机访问日志统计（q02）

### 3.1 access.csv

按题目给定内容创建（1 行表头 + 8 行数据，共 9 行）。

### 3.2 analyze.sh（scripts/q02.sh 内生成）

```bash
#!/bin/bash
# 用法: ./analyze.sh <csv文件>
if [ $# -ne 1 ]; then
    echo "用法: $0 <csv文件>" >&2
    exit 2
fi
csv="$1"

if [ ! -f "$csv" ]; then
    echo "错误: 文件 $csv 不存在" >&2
    exit 1
fi

# 1) 5xx 数量最多的前 2 个 path（次数降序，相同按字典序）
tail -n +2 "$csv" | awk -F, '$4 >= 500 && $4 < 600 {print $3}' \
    | sort | uniq -c | sort -k1,1nr -k2,2 | head -n 2

# 2) 全部数据行的平均 latency_ms（表头不计入），保留两位小数
tail -n +2 "$csv" | awk -F, '{sum += $5; n++} END {printf "平均 latency: %.2f\n", sum/n}'
```

### 3.3 运行结果

对 access.csv 运行：

```
      3 /api/orders
      2 /api/users
平均 latency: 193.75
```

（`uniq -c` 输出的次数带右对齐前导空格，属正常现象）

对不存在的文件运行（错误进入 stderr，退出码非零）：

```
错误: 文件 missing.csv 不存在      ← stderr
exit=1
```

### 3.4 要点分析

- **管道分解**：`tail -n +2` 跳过表头 → `awk` 过滤状态码 500–599 并取出第 3 列 path → `sort` 让相同 path 相邻 → `uniq -c` 计数 → `sort -k1,1nr -k2,2` 按次数降序、次数相同按 path 字典序 → `head -n 2` 取前 2。
- **5xx 计数核对**：`/api/orders` 3 次（500、502、500）、`/api/users` 2 次（503、500）、`/login` 1 次（500），故前 2 名为 `/api/orders`、`/api/users`。
- **平均延迟核对**：(120+310+180+90+260+20+420+150) / 8 = 1550 / 8 = 193.75，`printf "%.2f"` 保留两位小数；表头被 `tail -n +2` 排除，不计入。
- **错误处理**：文件不存在时错误信息用 `>&2` 写入 stderr，`exit 1` 返回非零退出码，满足题目要求。

## 四、实验三：制造、解决并解释一次合并冲突（q03）

### 4.1 操作步骤（scripts/q03.sh）

1. `git init`，将默认分支命名为 `main`，创建 `config.txt`（`mode=normal`）并完成初始提交。
2. 新建分支 `feature-a`，把内容改为 `mode=safe` 并提交。
3. 回到 `main`（此时仍在初始提交），从初始 `main` 新建分支 `feature-b`，把内容改为 `mode=fast` 并提交。
4. 回到 `main`，先 `git merge feature-a`（快进合并，无冲突）。
5. 再 `git merge feature-b` → **冲突**。

### 4.2 冲突原因

`feature-a` 与 `feature-b` 都从初始提交（`mode=normal`）出发，各自把同一文件**同一行**改成了不同内容（`mode=safe` / `mode=fast`）。合并时 Git 找不到共同基线下的唯一答案，无法自动合并，于是产生冲突。冲突现场 `config.txt` 内容：

```
<<<<<<< HEAD
mode=safe
=======
mode=fast
>>>>>>> feature-b
```

### 4.3 冲突解决

手工编辑（保留 `mode=safe`，另加一行 `note=reviewed`），然后标记已解决并提交，完成本次合并：

```bash
printf 'mode=safe\nnote=reviewed\n' > config.txt
git add config.txt
git commit -m "merge feature-b: keep mode=safe, add note=reviewed"
```

### 4.4 验证结果

**git status**：`nothing to commit, working tree clean`（工作区干净）。

**最终 config.txt**：

```
mode=safe
note=reviewed
```

**git log --all --graph --decorate --oneline**：

```
*   8703ad7 (HEAD -> main) merge feature-b: keep mode=safe, add note=reviewed
|\
| * cac5500 (feature-b) feature-b: set mode=fast
* | e3b1f51 (feature-a) feature-a: set mode=safe
|/
* 733bff0 init: mode=normal
```

### 4.5 小结

- 合并冲突的本质：双方从同一基线修改了同一区域，Git 无法判断保留哪一份，需要人工决策。
- 解决流程：编辑冲突文件（删除 `<<<<<<<`/`=======`/`>>>>>>>` 标记）→ `git add` → `git commit`；也可用 `git checkout --ours/--theirs` 直接选取一侧。

## 五、实验四：修复并构建一页技术说明（q04）

### 5.1 任务与完整代码

按题目模板补全内容：加入一个带编号和 label 的公式并在正文中引用（`\eqref`）；加入一个 2 行 2 列表格，设置 `caption` 与 `label` 并在正文中引用（`\ref`）；最后用 `latexmk -pdf -halt-on-error` 构建 PDF，确认交叉引用不显示 "??"。`report.tex` 完整内容如下：

```latex
\documentclass{article}
\usepackage{amsmath}
\begin{document}
\title{Tool Report}
\author{Li Yunlong -- 25030021043}
\maketitle
\section{Result}

The mass--energy equivalence is given by Equation~\eqref{eq:einstein}:
\begin{equation}
    E = mc^2
    \label{eq:einstein}
\end{equation}

The sample data are listed in Table~\ref{tab:sample}.
\begin{table}[h]
    \centering
    \caption{Sample data}
    \label{tab:sample}
    \begin{tabular}{cc}
        \hline
        alpha & 2 \\
        beta  & 3 \\
        \hline
    \end{tabular}
\end{table}

\end{document}
```

### 5.2 构建与验证

```bash
# 安装依赖（首次需要；poppler-utils 提供 pdftotext 用于验证）
sudo apt update
sudo apt install -y texlive-latex-base texlive-latex-recommended texlive-latex-extra latexmk poppler-utils

# 构建 PDF（latexmk 自动重跑，保证交叉引用正确）
latexmk -pdf -halt-on-error report.tex
ls -l report.pdf

# 验证：PDF 中不应出现未解析引用 "??"（无输出即通过）
pdftotext report.pdf - | grep -n '??'
```

### 5.3 运行结果

- `report.pdf` 成功生成（1 页，约 62 KB），`ls -l report.pdf` 确认存在；
- latexmk 自动重跑 2 次编译，正文中公式引用 `\eqref{eq:einstein}` 显示为 **(1)**，表格引用 `\ref{tab:sample}` 显示为 **1**；
- `pdftotext report.pdf - | grep -n '??'` 无输出，检查脚本输出 `OK: PDF 中没有 ??`、`OK: 日志中无 undefined references`。

### 5.4 要点分析

- **公式编号与引用**：`\begin{equation} … \label{eq:einstein} \end{equation}` 自动编号，正文用 `\eqref{eq:einstein}` 引用。
- **表格编号与引用**：`\caption{Sample data}` 生成标题，`\label{tab:sample}` 绑定编号，正文用 `\ref{tab:sample}` 引用；表格为严格的 2 行 2 列。
- **交叉引用机制**：引用信息写入 `.aux` 文件，需要编译两遍才能解析；`latexmk` 会自动重跑直到引用稳定，因此最终 PDF 不会出现 "??"。
- **中文支持**：模板为英文内容，pdflatex 可直接编译；如文档中需要使用中文，可安装 `texlive-lang-chinese`，用 `\usepackage[UTF8]{ctex}` 配合 `latexmk -xelatex` 编译（见 scripts/report-zh.tex）。

| 新环境 `git commit` 报 "Please tell me who you are" | 未配置 user.name / user.email | 提交前执行 `git config user.name`、`git config user.email` |
